# Kiwi 엔진 동작 실험

로컬 소스로 빌드한 Kiwi 0.24.1 XCFramework, 앱 모델, 실제 `KiwiProofreadingEngine`을 사용한다. 사용자 원고는 읽지 않는다. 앱 코드는 수정하지 않았다.

```sh
H=Vendor/Kiwi/Kiwi.xcframework/macos-arm64_x86_64
xcrun swiftc -O -parse-as-library Sources/JenaNoteKit/proofreading/KiwiProofreadingEngine.swift \
  Sources/JenaNoteKit/proofreading/KoreanOrthographyRules.swift "test/Kiwi실험_2026-10-31/probe.swift" \
  -I $H/Headers -L $H -lkiwi -lc++ -o /tmp/jena-kiwi-probe
/tmp/jena-kiwi-probe Sources/JenaNoteKit/Resources/KiwiModel
```

- E1 분석 옵션 차이: `kiwi_space`는 내부에서 `Match::all`만으로 다시 분석한다. 앱 옵션(OOV 문자 모델+오타)과 결과가 다르며 우열은 문장마다 갈린다. `리에느가`는 앱 옵션에서 `리에느가/NNG` 한 덩어리, 내부 옵션에서 `리에느/NNP 가/JKS`. `카셀리온`은 반대로 앱 옵션만 NNP로 묶는다.
- E2 `kiwi_space`: `리에느` 오탐의 직접 원인은 `reset_whitespace=1`이다. 공백을 지운 `그제야리에느가빵을`을 한 NNG로 분석해 붙인다(r0은 정상). 미등록 이름 내부에 공백을 넣는 경우(`카셀 리 온이`, `엘라 드 린과`, `서 준에게`)가 r0/r1 모두 있다. 앱 엔진의 보존 규칙이 7개 예문 모두에서 이를 막았다.
- E1b `dialect_cost`: `allowed_dialects=0`에서 3과 0의 결과가 동일하다. 효과 없음.
- E3 pretokenized `리에느/NNP`: 붙여 쓴 문장과 오타 문장까지 분석이 정확해지고 점수가 오른다. 단 `kiwi_space`에는 pretokenized를 넘길 수 없어 띄어쓰기에는 직접 반영되지 않는다.
- E4 builder `add_word(NNP)`: 4개 이름 등록 후 빌드 425ms. 등록한 이름은 분석·띄어쓰기 모두 정상이며 `그제야리에느가빵을받았다.` → `그제야 리에느가 빵을 받았다.`까지 복원한다. 미등록 `서준`은 여전히 `서 준`. `kiwi_builder_build(typos=nil)` 후 분석 옵션으로 오타 변환기를 넘기는 조합은 충돌 없이 동작했다.
- 표본 7문장 실험이며 정확도 벤치마크가 아니다. 원문 로그는 `probe.log`.

## 맞춤법 규정 대조 (2026-10-31 추가)

기준: `docs/자료/한글 맞춤법 표준어 규정 해설.pdf`(국립국어원 2018, 2017 개정 규정). `rules-probe.swift`는 규정 조항별 예문 65개를 실제 엔진에 넣고 기대값과 비교한다. `blocklist-probe.swift`는 비표준 형태소 차단(blocklist)+사용자 오타 규칙으로 Kiwi가 직접 교정 후보를 내는지 확인한다. 빌드 방법은 위와 같다(blocklist-probe는 엔진 파일 없이 단독 컴파일).

- rules-probe: 35/65 통과. 미통과는 앱 공백 보존 정책 4건, `kiwi_space`의 허용 붙여쓰기 분리 2건(47·49/50항), 형태 분석은 맞지만 표면형을 안 고치는 것 4건(됬·-치/-지·-컨대/-건대), Kiwi 사전이 비표준형을 정상 형태소로 수용 9건, 의미 판단 필요 5건, 어휘 대치 7건으로 나뉜다(`수출량을 늘인다`는 분리·의미 양쪽에 중복 집계). 원문은 `rules-probe.log`.
- blocklist-probe: 갈께·올찌·볼쑤록·깨끗히·솔직이 5건이 Kiwi 오타 경로로 교정됐다. 그럴껄(`꺼/NNB` 차단 필요)·꼼꼼이(조합 차단 불가)는 미해결. 정상 문장 8개 과교정 없음. 원문은 `blocklist-probe.log`.

## ① 허용 붙여쓰기 보존 적용 (2026-10-31)

`KiwiProofreadingEngine.permittedJoins`가 원문에 붙어 있던 경계 중 규정상 붙여 써도 되는 곳에는 Kiwi가 새 공백을 넣지 못하게 한다. 대상은 제47항 `-아/-어/-여` + 보조 용언(`하`는 앞 어간이 형용사일 때만, `먹고 싶어 하다` 같은 구는 제외)과 한자어 접미 성격의 `량·률·율·력`이다.

- 첫 시도의 "한 음절 명사 일반" 규칙은 의존 명사(`만`·`겸`·`등`·`씨`)를 막아 4건이 퇴행했고, NNG/NNP로 좁혀도 `책상위에`·`학교앞에서`·`산위에`·`오늘밤` 교정을 잃었다. 미등록 이름은 기존 보호가 이미 지키므로 이득이 없어 폐기하고 접미 목록으로 좁혔다.
- 규정 예문(`rules-probe-after-permitted-joins.log`): 35 → 36/65. 과교정 WRONG 2건(`꺼져간다`, `수출량`) 해소, 기존 통과 퇴행 0. 남은 WRONG 1건(`그럴껄`)은 ④ 범위.
- 보조 비교(`tradeoff-probe.log`, 규칙만 끈 같은 파일 대비): `먹어보았다`·`도와드린다`·`깨뜨려버렸다`·`에너지량` 4건만 바뀌고 나머지 19건 동일.
- 전체 471개 테스트 통과(`tests-permitted-joins.log`), `git diff --check` 통과.

## ② 규정 기반 공백 정책 (2026-10-31)

`permittedJoins`를 `orthographySpacing`으로 넓혀 붙일 자리(`joins`)와 띄울 자리(`splits`)를 함께 돌려준다. 앱의 공백 보존 정책은 `joins`에서는 기존 공백 삭제를 허용하고, `splits`에는 Kiwi가 붙여도 공백을 넣는다.

- 붙임: `-어 지다`(`지워 진다`), 형용사·`-하다` 형용사 + `-어 하다`(`예뻐 한다`, `행복해한다`), 체언 뒤 `뿐·대로·만큼`(`남자 뿐` → 조사). 관형사형 뒤(`웃을 뿐`, `아는 대로`)는 의존 명사라 그대로 띄운다.
- 띄움: 동사·보조 용언 + `-어 하다`(`먹고 싶어한다` → `싶어 한다`, `마음에 들어한다` → `들어 한다`). 원래 `kiwi_space`는 `하/VX` 앞 공백을 무조건 지워 제47항 예외를 어겼다.
- 규정 예문(`rules-probe-after-required-spacing.log`): 36 → 39/65, 퇴행 0. 남은 공백 MISS는 `할 지 모르겠다`(Kiwi가 어미 `-ㄹ지`를 `지/NNB`로 분석) 1건.
- 오작동 점검(`guard-probe.log`, 같은 파일에서 규칙만 끈 사본 대비 27문장): 바뀐 8건(`가고 싶어 했다`, `너만큼`, `놓여진다`, `열려진다`, `바빠한다`, `나뿐`, `셋뿐`, `추워한다`) 모두 규정 방향. `슬퍼한다`·`고마워한다`·`그뿐만 아니라`·`갈 뿐 아니라`·`할 수 있을 만큼` 등 19건 불변.
- 전체 472개 테스트 통과(`tests-required-spacing.log`), `git diff --check` 통과.

## ③ 형태소 기반 표기 규칙 (2026-10-31)

- 제40항 붙임 2 `contractedHaEdits`: Kiwi는 `넉넉치`·`넉넉지`를 모두 `넉넉/XR 하/XSA 지/EC`로 분석하고, 표면에 `하`가 없으면 `하` 토큰 길이가 0(탈락) 또는 1(축약)이다. 어근 끝 받침이 [ㄱ·ㄷ·ㅂ] 소리면 `지·건대·게·도록·다`, 그 밖이면 `치·컨대·케·토록·타`로 어미 자리만 바꾼다. `하지`처럼 하를 다 적은 형태와 `요컨대`·`결코` 같은 굳은 부사(MAG)는 대상이 아니다. 길이 0 토큰은 단어별 필터에서 빠지므로 전체 토큰으로 먼저 계산한다.
- 제35항 붙임 2: `됬`은 표준 음절이 아니므로 `KoreanOrthographyRules`에서 `됐`으로 바꾼다.
- 규정 예문(`rules-probe-after-contracted-ha.log`): 39 → 43/65, 퇴행 0.
- 오작동 점검(`ha-guard-probe.log`, 하 규칙만 끈 사본 대비 30문장): 바뀐 10건(`익숙지`, `답답지`, `갑갑지`, `거북지`, `편치`, `다행치`, `연구토록`, `생각다 못해`, `깨끗게`, `넉넉지·섭섭지` 동시 교정 문장) 모두 규정 방향. `흔치`·`무능타`·`정결타`·`만만찮다`·`아무렇지`·`같지`·`괜찮다` 등 정상 표기 불변.
- 범위 밖 발견: `생각지도 못했다` → `못 했다`. 규칙을 모두 끈 사본에서도 같으며 Kiwi가 `못/MAG 하/VV`로 분석한 결과다. `-지 못하다`의 보조 용언 `못하다`는 붙여 써야 하므로 공백 정책 후속 과제로 남긴다.
- 전체 474개 테스트 통과(`tests-contracted-ha.log`), `git diff --check` 통과.

## ④ blocklist·오타 규칙·부사 규칙 (2026-10-31)

- 제53항: 오타 규칙 `찌→지`, `쑤→수`, `께→게`(비용 1.5)를 기본 오타 집합 사본에 더하고, 모델 사전에 정상 형태소로 들어 있는 `ᆯ께`·`을께`·`ᆯ께요`·`을께요`·`께/EF`를 blocklist로 막았다. `-ㄹ껄`은 Kiwi가 `거/NNB+ᆯ/JKO`로 분석해 Joiner가 띄우므로 `KoreanOrthographyRules`에서 ㄹ 받침 + `껄`(요) → `걸`로 바꾼다(`껄껄`은 제외).
- `-ㄹ걸`(어미)과 `-ㄹ 걸`(것을)은 뜻으로만 갈리므로 원문이 붙어 있으면 공백을 넣지 않는다. 기존에는 바르게 쓴 `그럴걸 그랬다`도 `그럴 걸`로 띄웠다.
- 제51항 `adverbSuffixEdits`: Kiwi는 틀린 부사를 어근 + `이/히`(XSM)로 나눈다. ㅅ 받침·겹친 명사(두 토큰으로 나뉜 `틈 틈` 포함)·부사·비`-하다` 용언 어간 뒤는 `이`, `-하다` 어근(`kiwi_find_morphemes(…, "XR")`) 뒤는 `히`. ㄱ 받침이 아닌 XR 어근은 규칙만으로, 나머지는 바꾼 형태가 사전 부사(MAG)일 때만 바꾼다(ㄱ 받침은 `깊숙이`/`넉넉히`처럼 갈림). 사전에 통째로 들어 있는 `깨끗히`·`일일히`·`번번히`·`틈틈히`·`곰곰히`·`솔직이`는 blocklist.
- 중간 수정: 반복형 판별이 `꼼꼼`·`섭섭` 같은 의태 어근까지 명사로 보아 `-이`로 고정하던 문제를 NNG로 좁혔고, 사전에 없는 `간편히`·`나른히`·`섭섭히` 때문에 XR 규칙 단독 판정을 추가했다. `껄껄 웃었다`→`껄걸` 퇴행은 `껄`을 제외해 해소했다.
- 규정 예문(`rules-probe-after-blocklist.log`): 43 → 50/65, WRONG 0, 퇴행 0.
- 대상·정상 비교(`blocklist-guard-probe.log`, ④를 끈 사본 대비): 대상 30개 중 29개 교정(남은 `갈찌라도`는 Kiwi가 `갈찌/NNG` 미등록 명사로 분석). 정상 44문장(`찌개`, `쑤다`, `선생님께`, `아들께`, `깊숙이`, `넉넉히`, `특히`, `급이 다르다` 등) 모두 입력 그대로이며 변화는 `그럴걸` 띄움 해소 1건.
- 이전 점검 하네스(`guard-probe`, `ha-guard-probe`, `tradeoff-probe`) 재실행 결과 퇴행 없음. 전체 476개 테스트 통과(`tests-blocklist.log`), `git diff --check` 통과.
