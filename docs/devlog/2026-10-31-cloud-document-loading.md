# 클라우드 드라이브 문서 연속 열기 안정화

2026-10-31. 문서를 iCloud·Google Drive 연결 폴더에서 열 때, 읽는 도중 사이드바로 다른 파일을 여러 개 열면 열리지 않거나 앱이 종료되는 문제가 보고됐다(크래시: `EditorViewController.viewDidLayout` → `ScrollReadingPosition.scroll` → 문자열 범위 예외).

## 원인
- 사이드바 전환(`swapDocument`)은 비동기로 파일을 연다. 클라우드 파일은 읽기에 수 초가 걸려, 그 사이 다른 파일을 누르면 두 요청이 모두 "지금 문서를 교체"하게 된다. 늦게 도착한 쪽이 이미 닫힌 이전 문서를 다시 닫고 창을 두 번째 문서에도 붙여, 창 하나가 두 문서에 매달렸다.
- 열기 실패를 `guard error == nil … else { return }`로 조용히 삼켜 아무 안내 없이 끝났다.
- UTF-8로 해석되지 않는 데이터를 빈 문서로 열었다. 이후 편집·자동 저장이 원본을 빈 내용으로 덮어쓸 수 있는 데이터 손실 경로였다.
- 읽던 자리 복원 스크롤이 스토리지 편집 중에도 레이아웃 매니저를 조회해, 줄어든 문자열을 범위 밖에서 읽고 예외로 종료될 수 있었다(재현 테스트로 확인).

## 변경
- 사이드바 전환은 최신 요청만 적용한다. 앞선 요청의 결과는 버리고, 아무 창에도 붙지 않은 문서는 닫는다. 교체 대상은 클릭 당시가 아니라 지금 창이 보여주는 문서다.
- 열기 실패는 창 시트로 알리고 사이드바 선택을 현재 문서로 되돌린다(사용자 취소 제외).
- UTF-8이 아닌 파일은 열기를 실패시킨다. 진짜 빈 파일은 그대로 열린다. 외부 변경 자동 리로드에서는 기존처럼 실패를 무시하고 현재 내용을 유지한다.
- `ScrollReadingPosition.scroll`은 스토리지 편집 중이면 적용하지 않고 false를 돌려주며, 에디터는 복원 대기를 유지해 다음 레이아웃에서 다시 시도한다.

## 검증
- `DocumentSwapTests`: 문서 열기를 주입해 완료 순서를 조절한다. 늦게 도착한 앞 요청이 창을 가져가지 않음, 먼저 도착한 낡은 결과가 적용되지 않음, 실패가 시트로 표시됨, 해석 불가 데이터가 빈 문서로 열리지 않음. 최신 요청 가드를 끄면 앞의 두 테스트가 실패한다.
- `ScrollReadingPositionTests`: 편집 중 축소 상황에서 가드를 끄면 크래시와 같은 `NSRangeException`이 난다.
- 전체 485개 테스트 통과, 릴리스 빌드 통과. 실제 클라우드 드라이브에서의 수동 확인은 하지 않았다.

## 남은 과제
- NSDocument 읽기가 메인 스레드에서 일어나 클라우드 내려받기 동안 화면이 멈춘다. `canConcurrentlyReadDocuments`는 `MarkdownSerializer.parse`(AppKit 속성·첨부 이미지)의 스레드 안전성 검토 후 결정한다.
- 내려받기 중 FSEvents로 외부 변경 리로드가 반복될 수 있다. 실제 드라이브에서 관찰 후 판단한다.
- EUC-KR 등 비UTF-8 텍스트 파일은 이제 열리지 않는다(이전에는 빈 문서로 열렸다). 필요하면 인코딩 감지·변환 열기를 별도로 설계한다.
