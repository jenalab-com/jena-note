## 릴리스 범위

v1.0.1 → **v1.1.0**. 읽기 모드(책 보기)라는 큰 기능 추가 + 빌드 인프라 전환을 묶은 **minor bump**.

| 영역 | 내용 |
| --- | --- |
| **SPM 전환** | `swiftc` 직접 컴파일 → Swift Package Manager(`JenaNoteKit` 라이브러리 + `JenaNote` 실행 + `JenaNoteKitTests`). `make build`/`run` 컨벤션 유지(Makefile 래핑), `make test` 추가. 순수 로직에 회귀 테스트 11개. |
| **읽기 모드** | `⌘⇧R`·툴바·메뉴로 편집 ⇄ 읽기 토글. 한글 35자 가운데 컬럼, 스크롤 / 가로 페이지 넘김 선택, 읽기 전용 글자 크기(0.8~2.0×), 7개 언어 라벨. |
| **폰트·행간** | 읽기 모드 폰트 명조(AppleMyungjo)/고딕(시스템) 토글, 행간 좁게·보통·넓게(기본 1.5배). |
| **레이아웃 수정** | `.fullSizeContentView` 제거로 상단바·작업화면 분리(페이징 상단 가림·사이드바 폴더 버튼 트래픽라이트 겹침 해소), reader 스크롤 레이아웃 정석화. |
| **진짜 페이지네이션** | scroll-offset 흉내(줄 잘림) → 페이지마다 독립 NSTextContainer. 안 들어가는 줄은 통째로 다음 페이지로 흘려 **줄이 잘리지 않는** 구조. |

## 결정

### 버전을 v1.1.0으로 한 이유
읽기 모드는 새 기능군이고 SPM 전환은 빌드 인프라 변경이라, SemVer 상 minor bump(v1.1.0)가 자연스럽다. v1.0.1의 patch 정책과 달리 이번엔 기능 규모가 분명해 minor 채택.

### 설계·구현 추적
설계(spec)·계획(plan)은 `docs/superpowers/specs/2026-06-21-reading-mode-design.md`, `docs/superpowers/plans/2026-06-21-reading-mode.md`에 남겼다. 구현은 subagent-driven 7개 task + task별 리뷰 + 최종 통합 리뷰를 거쳤고, 이후 실제 GUI e2e에서 발견된 레이아웃 버그와 페이징 줄 잘림을 systematic-debugging으로 근본 수정했다.

### 페이징 방식 전환
초기 구현은 scroll-offset 점프(전자책 근사치)였으나 실사용에서 줄 잘림이 근본적으로 해소되지 않아, 멀티 NSTextContainer 기반 진짜 페이지네이션으로 재작성했다. 트레이드오프: 페이징 모드에서 텍스트 선택 비활성(←/→ 키 충돌 회피).

### 알려진 미검증 항목 (수동 e2e 권장)
GUI 동작은 헤드리스로 검증 불가해 사람이 직접 확인한다: 읽기 진입 후 문서 dirty 미발생(닫을 때 저장 프롬프트 없음), 읽기 중 사이드바 파일 교체, 다크모드 배경.
