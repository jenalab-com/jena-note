# 작품 검색과 백그라운드 요약 분리

## 문제와 결정

사용자가 기원 작품 4,312조각 중 413조각 처리에 약 90분이 걸리는 문제를 보고했다. 전체 요약 완료를 기다리지 않고 관련 원문으로 채팅을 진행하도록 요청했고, 설계 문서 작성 후 구현을 승인했다.

- 설계: `../superpowers/specs/2026-10-28-background-work-context-design.md`
- 결정: `../architecture.md` ADR-0017

## 변경

- `AIWorkIndexStore.prepareForSearch`: 최신 원문 비동기 스캔과 기존 요약 결합을 독립 수행. 진행 중인 요약은 기다리거나 취소하지 않는다.
- 채팅은 검색 스냅샷을 받고 기존 미래 화/제외 필터를 적용한 뒤 원문으로 진행한다.
- `AIWorkRetrieval`: 질문·보조 문맥 기반 로컬 선검색을 백그라운드에서 수행하고 관련 원문/인접 조각을 첫 탐색 프롬프트에 제공한다. 전체 허용 자료가 24조각/160KB 이하면 탐색 왕복 없이 원문을 전달한다.
- 기존 요약이 없는 검색 목록은 발췌로 표시한다. 발췌 미리보기 때문에 요약 작업이 완료된 것으로 저장하지 않는다.
- 질문 관련 자료와 열린 문서/직전 화 우선순위를 추가한다. 진행 중인 추론은 유지하며 원문 변경 시 다음 작업 전에 재스캔한다.
- 전체 JSON 저장을 8회 완료/5초 단위로 묶는다. 정상 완료·취소·오류에는 저장하며, 기존 v2/2,400바이트 규격은 유지한다.
- 상태 문구에서 검색 가능 여부와 백그라운드 처리 조각 수를 구분한다. README의 관련 기능 설명만 갱신했다.

## 검증 및 발견 사항

- 기존 테스트의 '채팅 전송이 백그라운드 작업을 시작' 및 '작은 작품에도 탐색 CLI를 호출' 전제를 새 동작에 맞춰 수정했다.
- 실제 `AIClient`/프로세스 경로는 가짜 CLI 실행 파일로 검사한다. 외부 유료 모델 호출은 없다.
- 요약 응답을 의도적으로 보류한 채팅, 캐시 재사용, 변경/제외 자료, 미래 화 제외, 우선순위, 저장 묶음, 취소 후 늦은 검색 결과를 검증한다.
- 최종 `swift test`: 408개 테스트, 실패 0개(2026-10-28). 로그: `/tmp/jena-background-full-test.log`.
- 합성 원문 4,312조각 로컬 검색: 약 0.51초. 요약 생성·디스크 스캔·외부 AI 응답을 포함하지 않는 단일 실행 측정이며 실제 기원 작품의 속도 보장이 아니다.
- `git diff --check`: 통과.
- 최종 `swift build -c release --product JenaNote`: 성공. 로그: `/tmp/jena-background-release.log`. 앱 번들 교체·설치·재실행은 수행하지 않았다.

## 한계와 보존

- 실제 기원 작품의 지연 시간·요약 품질·실패율은 측정하지 않았다. 합성 자료 검색 시간과 실제 AI 응답 시간을 혼동하지 않는다.
- 큰 작품은 여전히 필요에 따라 최대 4회 탐색 호출을 사용한다. 문자열 선검색은 의미 검색을 대신하지 않는다.
- 원문 스캔은 질문마다 수행한다. 전체 JSON 저장은 횟수만 줄였고 직렬화/쓰기는 여전히 메인 큐다. 장기적으로 증분 저장을 검토할 수 있다.
- 비정상 종료 시 저장 전 최대 7회 추론 결과를 재생성할 수 있다. 정상 중지 시 완료 결과는 저장한다.
- 수정 전 파일은 `/var/folders/jy/d4hl_blj2wgf55g7gg6nnz0m0000gn/T/jena-context-before-02zhxleg`에 별도로 보존했다. 진행 중인 앱, 기원 원고·설정·캐시는 변경하지 않았다.
