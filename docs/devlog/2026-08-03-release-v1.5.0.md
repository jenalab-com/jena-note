# v1.5.0 릴리즈 — 책갈피·이어읽기, 읽기 서체 선택 (2026-08-03)

## 요약

읽기 모드가 두 방향으로 자랐다. 하나는 **읽던 자리를 잃지 않는 것**(이어읽기·책갈피, 7월 작업), 다른 하나는 **읽는 모양을 고르는 것**(서체·굵기 선택, 8월 작업). 후자에서는 표시 설정이 파일을 오염시킬 수 있는 경로를 하나 찾아 막았다.

## 새 기능

### 이어읽기 (AC-11)
- 읽기 모드에서 읽던 위치를 문서별로 자동 기억·복원 (`ReadingProgressStore`, UserDefaults, 상한 300건)
- 문자 오프셋을 진리의 원천으로 삼아 폰트·행간·폭·페이지 모드가 바뀌어도 읽던 문장이 화면에 남는다
- 문맥 스니펫 재동기화 — 문서 앞부분이 편집돼도 위치가 밀리지 않는다 (`ReadingAnchor`)
- 상세: ADR-0008

### 책갈피 (AC-12)
- ⌘D 토글 — 지금 보이는 화면에 책갈피가 있으면 해제, 없으면 추가
- 툴바 팝오버로 목록·점프·삭제. 아이콘이 `bookmark` ↔ `bookmark.fill` 로 현재 화면 상태를 알린다
- 미리보기 문구는 저장하지 않고 그릴 때마다 현재 본문에서 뜬다 (편집돼도 실제 문장과 일치)
- 상세: ADR-0008a

### 읽기 서체·굵기 선택 (AC-13, 신규)
- 툴바 서체 팝업 — **설치된 서체만** 노출, 각 항목을 그 서체로 그려 고르기 전에 생김새가 보인다
  - 명조(자동)·고딕(자동) + KoPub 바탕·나눔명조·김정철 명조·Apple 명조·Apple SD 고딕·나눔고딕·본고딕·프리텐다드
- 굵기 3단 — 연하게/보통/굵게. 서체에 없는 굵기는 `NSFontManager` 가 가장 가까운 것으로 대체
- **KoPub 바탕 Medium·Bold 앱 번들 동봉** — 사용자 머신의 폰트 설치 상태와 무관하게 같은 조판
- 상세: ADR-0009

## 설계 노트 — 표시 설정이 파일을 바꿀 뻔한 자리

굵기 기능을 넣기 전에 두 코드가 만나는 지점을 확인했다.

1. `MarkdownSerializer` 는 **볼드 trait 으로 `**` 를 판정**한다.
2. `ReaderMetrics.originalFont` 는 조판 중 새로 입력된 구간(`.mdBaseFont` 백업 없음)의 볼드 trait 을 **"사용자가 준 볼드"로 물려받는다**.

즉 본문 굵기를 '굵게'로 둔 채 읽기 모드에서 글을 치면, 저장 시 그 문장이 통째로 `**볼드**` 가 된다. 표시 설정이 파일 내용을 바꾸는 사고다.

`.mdReaderBold` 표시를 도입해 **두 경로 모두**에서 걸렀다 — 조판을 벗길 때(`unstyled`)와, 조판된 채 저장될 때(`MarkdownSerializer`). 후자는 기존 테스트 `testStyledTextStillSerializesWithBoldIntact` 가 "조판 해제를 잊은 저장 경로가 실재한다"고 알려 줘서 발견했다. 하나만 막았으면 그 경로로 샜다.

### 서체 해석을 패밀리 기반으로 바꾼 이유

굵기 전환은 `NSFontManager.font(withFamily:traits:weight:size:)` 가 패밀리 안에서 가장 가까운 굵기를 골라 준다. 이 API 가 패밀리 이름을 요구하는데, 서체마다 굵기 체계가 제각각이다.

| 서체 | 보유 굵기 | weight 3 / 5 / 9 |
|---|---|---|
| KoPub 바탕 | Light/Medium/Bold | Light / Medium / Bold |
| 나눔명조 | Regular/Bold/ExtraBold | Regular / Regular / Bold |
| Apple 명조 | Regular 단일 | Regular / Regular / Regular |
| Apple SD 고딕 | Thin~Heavy 9종 | Thin / Regular / Bold |

서체별 하드코딩은 유지가 불가능해서 패밀리 이름 후보 배열로 통일했다. 부수 효과로 "KoPub 바탕은 Regular 스타일이 없어 패밀리 이름으로 부르면 Light 가 잡힌다"는 함정도 정리됐다.

## 검증

- 테스트 153개 전체 통과 (읽기 조판 왕복 22개 — 굵기 안전성 9개 신규)
- **뮤테이션 검증** — `.mdReaderBold` 로직을 일부러 제거하고 돌려 정확히 3개가 실패하는 것을 확인. 통과만 하고 아무것도 잡지 않는 테스트가 아님을 증명
- 번들 글꼴 등록 검증 — 프로브 앱으로 `CTFontCopyAttribute(kCTFontURLAttribute)` 조회. 시스템에 같은 폰트가 설치된 상태에서도 **번들 경로**가 반환되어 우선순위 확인
- 현지화: 신규 키 14개 × 7개 언어 = 98항목

## 남긴 부채 (fast-follow)

- 굵기를 '굵게'로 두면 본문과 사용자 `**볼드**` 가 화면상 구분되지 않는다 (저장 데이터는 정확히 갈라짐). 사용자 볼드만 한 단계 더 굵게 그리는 방안 검토
- 읽기 툴바 아이템이 8개로 늘어 좁은 창에서는 오버플로 메뉴로 밀린다 — 우선순위 정리 필요
- 번들 글꼴로 앱이 2.8MB → 15MB. 서브셋팅으로 줄일 수 있으나 임의 한자 입력 시 두부(□) 위험이 있어 보류
- 육안 확인 미완 — 서체 팝업 항목이 각자 서체로 그려지는지는 실사용에서 확인 필요
