# 선택 문장 검사 Kiwi 전환

짧은 선택 문장을 검사하는 데 수초가 걸리고 작품 요약까지 기다리던 문제를 줄이기 위해 기본 검사 엔진을 Kiwi 0.24.1로 전환했다. 원문/제안 비교, 명시적 적용, Undo, 충돌 검사와 취소 화면은 그대로 유지한다.

- 공식 정적 XCFramework와 104MB base 모델을 버전·SHA-256으로 고정했다. 모델 다운로드는 빌드 단계에서만 수행한다. 대용량 생성 모델은 Git에 넣지 않고 `make build`/`make test`가 준비한다. 코드·모델 및 포함 라이브러리의 라이선스와 고지는 앱 리소스에 복사한다.
- 전용 직렬 작업 스레드에서 한 번 로딩하고 재사용한다. 편집기가 열리면 비동기로 준비한다. 작품 요약 큐와 별도의 요청 큐를 사용하며 대기 포함 제한은 10초다. 취소 뒤 늦은 네이티브 결과는 적용하지 않는다.
- Kiwi 기본 오타 분석과 띄어쓰기 API를 결합했다. 오타로 판단한 어절과 잘못된 과거 어미만 재결합하고, 분석된 고유명사·외국어·숫자·URL은 보존한다. 줄바꿈·탭·연속 공백을 그대로 유지한다.
- 초기 실험의 deprecated builder/spacing 조합은 충돌해 채택하지 않았다. `kiwi_init`과 별도 준비된 오타 변환기를 사용한다. 오타를 정상 표기로 허용하는 사전과 이형태 통합도 꺼서 오류 후보가 드러나도록 했다.
- 한계: 복잡한 비문 판단과 모든 오타 교정을 제공하지 않는다. 고유명사 보호도 형태소 분석 결과에 의존한다. 사용자 사전 UI와 입력 중 자동 밑줄 검사는 별도 작업이다.

검증: 전체 444개 테스트 통과. 준비 후 짧은 예문은 약 0.1~1.8ms, 같은 문장 30회 중앙값은 약 0.23~0.26ms였다. 이 시간은 엔진 호출 기준이며 UI 표시 시간은 제외한다. 자세한 재현 절차와 실제 배포 모델 검증은 `test/Kiwi_2026-10-30/`에 기록한다.

설치된 앱과 실행 중인 사용자 원고를 바꾸지 않고 `.build/JenaNote-Kiwi-review.app`에 별도 빌드한다. 커밋·푸시는 수행하지 않는다.

배포 검증: 릴리스 빌드 성공. 별도 앱의 모델 10개 파일과 제3자 고지 10개 파일이 소스 리소스와 SHA-256 기준으로 일치했다. 배포 모델을 사용한 새 프로세스 첫 검사는 준비 포함 약 2.57초, 이후 예문은 약 0.1~1.6ms였다. `되요.`는 교정하지 못했다. arm64 기기에서 검증했으며 Intel 및 구형 macOS 실기 검증은 수행하지 않았다.
