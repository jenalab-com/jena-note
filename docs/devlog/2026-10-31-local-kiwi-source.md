# Kiwi 소스 확인·수정용 로컬 빌드 전환

## 목적과 범위
공식 릴리스 바이너리만 받아 쓰던 구조에서 소스를 직접 읽고 변경할 수 있는 구조로 전환한다. 교정 알고리즘·모델·개인 사전 동작은 변경하지 않는다. 앞선 사전 UX와 교정 품질 수정도 유지한다.

## 구현
- Kiwi v0.24.1 커밋 `724d00718f527bac3f8aef2f6ae3b6523b2aae74`의 엔진 소스를 `Vendor/Kiwi/source`에 스냅샷으로 보관했다. 필요 의존성의 정확한 커밋과 포함 범위는 `upstream.json`으로 추적한다. 원본 파일은 무수정이다.
- CMake로 macOS arm64/x86_64 정적 라이브러리를 각각 컴파일하고 lipo/XCFramework로 묶는다. iOS 산출물은 만들지 않는다. 이전 바이너리는 새 빌드 성공 뒤에만 교체한다.
- `Package.swift`의 원격 URL을 로컬 path로 교체했다. 소스·빌드 설정 지문을 검증하여 오래된 라이브러리 사용을 막는다.
- 최초 `bootstrap-kiwi`와 이후 오프라인 `prepare-kiwi`/`rebuild-kiwi`를 분리했다. 큰 모델은 기존 리소스 경로/Git 제외 정책을 유지한다.
- README에 CMake 준비·첫 빌드·재빌드·소스 탐색 순서·새 환경 복사 절차를 기록했다. 기존 배포 라이선스를 유지하고 바이너리 출처 설명을 수정했다.

## 소스에서 확인한 내용
`Spacing.cpp`에서 공백 초기화 후 형태소 분석과 품사별 공백 재조합을 한다. 앱은 `capi/kiwi_c.cpp`를 통해 이를 호출한다. `KiwiBuilder::addWord`/C API `kiwi_builder_add_word`도 있으나 앱의 개인 사전 제외 기능과는 별개다. 내부 사용자 사전 연동이나 모델 학습 변경은 별도 검토 대상이다.

## 검증
아래에 최종 빌드/회귀 결과를 기록한다. 원본 C++ 컴파일 경고는 로그에 보존하며 이번 변경에서 제3자 코드를 임의 수정하지 않는다.

검증 결과: 원본/의존성 고정 체크아웃과 스냅샷 897개 파일 바이트 일치. arm64+x86_64 소스 빌드 및 lipo 확인, SwiftPM의 로컬 BinaryTarget 경로 확인. 원격 바이너리 캐시와 분리한 `.build/kiwi-validation`에서 전체 469개 테스트 실패 0. 외부 연결 차단 샌드박스 안에서 릴리스 Swift 빌드 통과(중첩 샌드박스 충돌을 피하려고 내부 SwiftPM sandbox만 해제, 외부 network-outbound 차단 유지). 일반 `make build` 앱 패키징 통과. 오프라인 사전 검사의 정상·소스 변경·라이브러리 메타데이터 누락·모델 버전 불일치 시나리오 확인 및 원본 복원. 셸 구문·diff 검사 통과.

최초 C++ 빌드 중 소스 지문 계산 스크립트를 정리하여 이전 지문과 일치하지 않는 산출물이 거부되었고, 변경 확정 후 재빌드해 통과했다. C++ 원본의 컴파일 경고는 남아 있으며 런타임 테스트는 현재 Apple Silicon 환경에서 수행했다(Intel은 교차 컴파일/아키텍처 확인). 증거: `test/Kiwi소스_2026-10-31/`. 설치 앱 교체·커밋·푸시는 수행하지 않았다.
