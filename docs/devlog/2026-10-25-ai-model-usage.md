# AI 대화 로딩·모델 선택·사용량

## 변경과 이유
- 응답 대기 막대를 대화 스크롤 영역의 마지막 요청 바로 아래에 배치했다. 완료·실패·취소 시 사라지며 문서 전환 시 이전 요청의 로딩이 남지 않는다.
- 요청 입력란 아래에 모델 선택과 사용량, 새로고침 버튼을 추가했다. 기존 macOS 기본 컨트롤과 색상, 앞서 요청한 채팅 배치를 유지한다.
- 선택한 모델은 제공사별로 기억하고 요청의 `--model` 인자로 전달한다. 직접 모델 ID 입력도 지원하며 기존 CLI 설정 파일은 수정하지 않는다. 요청 중 모델 선택은 비활성화한다.
- 현재 문서 대화에서 완료된 요청의 CLI 보고 토큰 합계와 계정 전체 사용률을 구분한다. 캐시나 추론 토큰을 중복 합산하지 않으며, 사용량을 반환하지 않은 응답은 추정하지 않는다.

## 공급사별 차이
- Claude: CLI의 stream-json 제어 요청 `initialize`와 `get_usage`로 모델 목록과 계정 한도를 조회한다. 세션(5시간)·주간·모델별 주간 한도 및 활성화된 월간 추가 사용 항목만 표시한다. 설치된 CLI에서 추론 없이 실제 조회를 확인했다. 오래된 CLI가 제어 요청을 지원하지 않으면 조회 불가 상태로 처리한다.
- Codex: App Server의 `model/list`, `account/rateLimits/read`를 사용한다. `primary`가 항상 세션 한도라고 가정하지 않고 반환된 기간을 읽는다. 여러 한도 묶음을 보존한다. 로그인된 계정에서 실제 모델 목록과 주간 사용률 조회를 확인했다.
- Gemini: 문서에 명시된 모델 선택 후보와 직접 ID 입력을 제공한다. 현재 사용 중인 headless JSON에는 토큰 통계가 있지만 계정 한도 조회는 연결하지 못했다. 계정 한도 조회 불가 안내와 CLI `/stats model` 안내를 제공한다.
- Grok: JenaNote 전용 프로필의 `models` 결과로 선택 목록을 채운다. 현재 전용 프로필은 로그인되지 않았으며 CLI가 반환한 기본 후보를 확인했다. 응답 JSON의 토큰 통계는 집계하되 계정 한도는 조회 불가로 표시한다.
- 월간 한도가 없는 계정이나 수치가 없는 항목을 임의의 0%로 만들지 않는다. 초기화 시각은 사용률 툴팁에서 확인한다.

## 구현과 운영
기존 프로세스 실행기에 작은 JSON 제어 메시지를 주고받는 stdin 파이프를 추가했다. 기존 글 요청은 계속 비공개 임시 파일 stdin을 사용한다. 메타데이터 조회에는 글이나 모델 추론 요청을 보내지 않고, 인증은 CLI에 맡긴다. 시간 제한·취소·출력 크기 제한을 유지하며 조회가 끝나면 이번 작업에서 생성한 프로세스 그룹만 회수한다. 사용자의 기존 CLI 프로세스와 앱은 종료하지 않는다.

채팅창 닫기 후 설정 변경 알림으로 사용량 조회가 다시 시작되지 않도록 중지 상태를 검사한다. 계정 데이터는 메모리에서 필요한 모델·한도 항목만 UI에 전달하고 저장하거나 로그로 출력하지 않는다.

## 검증 과정
- 기간별 한도와 모델별 한도, 미제공 값, 토큰 중복 합산 방지, 모델 인자 전달, JSON 제어 응답 순서, 로딩 위치를 테스트한다.
- 테스트 픽스처의 정수 사용률과 JSON 숫자를 모두 처리하도록 숫자 변환을 보완했다.
- 전체 테스트 중 메타데이터 요청과 추론 요청이 같은 테스트 기록 파일을 쓰는 충돌을 발견해 픽스처를 분리했다.
- 기존 소스는 작업 전 임시 백업했고, 기존 읽기 모드·AI 편집·로그인 변경을 보존했다.
- 최종 전체 테스트 209개 통과. 릴리스 빌드·임시 서명 검증·Info.plist 검사 완료: `.build/ai-model-preview-97TeS6/JenaNote.app`.
