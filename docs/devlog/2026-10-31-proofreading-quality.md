# 맞춤법·띄어쓰기 후보 품질 개선

## 재현과 원인
실제 배포 Kiwi 모델에서 `오랫만`은 그대로, `몇일`은 `몇 일`, `않되요`는 `안 되요`로 나왔다. `서준은학교에갔다`는 고유명사 보호가 어절 전체에 적용되어 띄어쓰기가 막혔다. 기존 테스트 통과는 기능 동작 증거이며 언어 품질 전반을 보장하지 않았다.

## 구현
- 이름과 붙은 명사·조사 내부만 보호하여 뒤 문장을 띄어 쓸 수 있게 한다.
- 독립적인 표기 규칙 9개를 추가한다: 오랫만, 몇일/몇 일, 않되요/않 되요, 되요, 안되요, 눈꼽, 머릿말, 웬지, 할께요. 단어와 제한된 조사 경계만 매칭한다.
- URL·숫자·외국어 구간은 규칙에서 제외한다. 개인 사전 필터는 최종 후보에서 해당 수정만 제외한다.
- 문장 내부 중복 공백은 정리하고, 앞뒤 공백·탭·CRLF·빈 줄은 유지한다.
- 기존 후보 표시, 명시적 적용, Undo 흐름을 유지한다. 모델 추가 다운로드나 외부 원고 전송은 없다.

## 검증 및 한계
실제 Kiwi를 호출하는 회귀 예문에 `오랫만에 → 오랜만에`, `몇일 → 며칠`, `않되요 → 안 돼요`, `서준은학교에갔다 → 서준은 학교에 갔다`를 추가했다. 정상 표기/이름 부분 문자열/URL 보호, 이모지 UTF-16 위치, 사전 제외 시 같은 문장의 다른 오류 유지, 공백만 있는 입력과 줄 끝 두 칸 보존을 검사한다.

이름 판별과 일반 어휘 교정은 여전히 Kiwi 분석에 의존한다. 문맥 문법 오류를 전부 잡는 기능은 아니며 특히 부정 표현의 붙여쓰기는 문맥에 따라 다른 판단이 필요하다. 향후 실제 실패 예문을 회귀 자료로 추가해야 한다.

설계: architecture ADR-0025. 참고: [Kiwi 공식 저장소](https://github.com/bab2min/Kiwi), [국립국어원 오랜만 표기 안내](https://www.korean.go.kr/front/mcfaq/mcfaqView.do?mcfaq_seq=6374&mn_id=).

검증 결과: 집중 테스트 8개와 전체 468개 테스트 실패 0, 릴리스 `make build` 및 `git diff --check` 통과. 실제 Kiwi 예문과 반복 호출 시간을 포함한 로그는 `test/맞춤법개선_2026-10-31/`에 보존한다. 설치 앱 교체·실앱 수동 조작·커밋·푸시는 수행하지 않았다. 이전 사전 UI/다중 삭제 변경을 함께 유지한다.

## 정상 문장 공백 삭제 오탐 후속 수정
실제 제보 `그제야 리에느가 빵을 받았다.`를 검사하면 `그제야리에느가빵을 받았다.`로 제안하는 현상을 재현했다. 분석 결과 `리에느가`는 NNP가 아닌 NNG여서 이름 보호만으로 해결할 수 없었다.

기존 공백은 분석된 하나의 토큰 내부이거나 뒤에 조사·어미·접사가 오는 경우에만 삭제를 허용하도록 제한했다. 공백 추가 및 내부 중복 공백 정리는 유지한다. 특정 이름을 정답으로 하드코딩하지 않는다. 이는 정상 단어 경계를 우선 보존하는 정책으로, 잘못 띄어 쓴 일부 합성 명사를 붙이는 제안은 누락될 수 있다.

제보 문장과 이모지 포함 변형, 후보 목록이 비어서 툴팁을 생성하지 않는 경로를 회귀 테스트에 추가했다. `학교 에 → 학교에`, `안녕 하세요 → 안녕하세요`와 기존 붙어 있는 문장 분리도 함께 검증한다.
후속 검증 결과: 집중 9개/전체 469개 테스트 실패 0, 릴리스 빌드 및 diff 검사 통과. 증거는 같은 시험 폴더의 `rienne-*.log`. 수정 앱은 `.build/JenaNote.app`이며 실행 중인 설치 앱 교체·커밋·푸시는 하지 않았다.

## 규정상 허용된 붙여쓰기 보존
국립국어원 '한글 맞춤법, 표준어 규정 해설'(2018) 예문 65개로 엔진을 대조한 결과, Kiwi 띄어쓰기가 제47항에서 허용하는 보조 용언 붙여쓰기(`꺼져간다`, `도와드린다`)와 한자어 복합 명사(`수출량`)를 쪼개는 과교정을 확인했다. Kiwi 원본 `Spacing.cpp`는 수정하지 않고, 앱이 원문에 붙어 있던 해당 경계에 새 공백을 넣지 않도록 했다. `-어 하다`는 형용사 어간 뒤에서만 붙여 두고 `먹고 싶어 하다`처럼 구에 결합한 경우는 띄어쓰기 제안을 유지한다. 의존 명사와 일반 한 음절 명사(`책상 위`) 분리는 그대로 제안한다. 근거와 전후 비교는 `test/Kiwi실험_2026-10-31/`.

## 규정 기반 공백 붙임·띄움
기존 공백 보존 정책은 다음 토큰이 조사·어미·접사일 때만 삭제를 허용해 `지워 진다`, `예뻐 한다`, `남자 뿐이다`를 고치지 못했다. 제47항(`-어 지다`, 형용사 + `-어 하다`는 붙여 씀)과 제42항(체언 뒤 `뿐·대로·만큼`은 조사)에 해당하는 자리는 삭제를 허용한다. 반대로 Kiwi는 `하/VX` 앞 공백을 무조건 지워 `먹고 싶어 하다`처럼 구에 결합한 `-어 하다`(제47항 예외)를 붙이므로, 동사·보조 용언 어간 뒤의 `-어 하다`는 띄어쓰기를 제안한다. 이름 보호 구간은 두 규칙 모두 건드리지 않는다. 근거와 전후 비교는 `test/Kiwi실험_2026-10-31/`.

## 하 탈락·축약과 됬
`넉넉치`, `생각컨대`처럼 제40항 붙임 2를 어긴 표기는 Kiwi가 `어근 + 하 + 어미`로 정확히 분석하지만 오타 비용이 0이라 교정되지 않았다. 어근 끝 받침 소리([ㄱ·ㄷ·ㅂ] 여부)로 `지/치`, `건대/컨대`, `게/케`, `도록/토록`, `다/타` 중 맞는 어미를 정해 어미 자리만 바꾼다. 하를 모두 적은 형태와 굳은 부사는 건드리지 않는다. `됬`은 어떤 표준어에도 없는 음절이라 `됐`으로 바꾼다. `생각지도 못했다`를 `못 했다`로 띄우는 기존 동작은 별도 후속 과제로 남겼다.

## 비표준 형태소 차단과 -이/-히 부사
모델 사전에는 `ᆯ께`, `깨끗히`, `솔직이` 같은 비표준형이 정상 형태소로 들어 있어 오타로 잡히지 않았다. 해당 형태소를 분석 blocklist로 막고, 제53항 어미(`찌·쑤·께`)는 기본 오타 집합에 규칙을 더했다. 제51항 부사는 Kiwi가 `어근 + 이/히`로 나누는 점을 이용해 ㅅ 받침·겹친 명사·부사 뒤는 `-이`, `-하다` 어근 뒤는 `-히`로 정하되, ㄱ 받침처럼 규정 경향만으로 갈리지 않는 경우는 결과가 사전 부사일 때만 바꾼다. `-ㄹ껄`은 표기 규칙으로 고치고, 뜻으로만 갈리는 `-ㄹ걸`/`-ㄹ 걸`은 원문 띄어쓰기를 따른다. 정상 문장 44개에서 과교정은 없었다. 근거와 전후 비교는 `test/Kiwi실험_2026-10-31/`.
