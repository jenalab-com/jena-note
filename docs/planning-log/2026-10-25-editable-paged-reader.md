# 페이지 읽기 화면 직접 편집과 점진적 조판

## 문제와 선택

읽다가 문장을 고치기 위해 스크롤 조판으로 전환하면 읽던 책의 배치가 바뀐다.
사용자가 페이지를 유지하는 직접 편집을 요청했다. 스크롤 전환, 별도 문단 편집창,
페이지 직접 편집 중 세 번째를 선택한다. 기존 문서 및 미커밋 수명 관리 수정은 보존한다.

## 가정과 범위

- AppKit/TextKit 1, 기존 MarkdownDocument와 읽기 표시 서식 변환을 유지한다.
- 한 문서의 편집은 메인 스레드에서 수행한다. 화면에 붙은 TextKit 객체를 작업 스레드와 공유하지 않는다.
- 정확한 전체 쪽수는 입력 직후 잠시 미확정이어도 되지만 입력·저장은 기다리지 않아야 한다.
- 입력 때문에 뒤쪽 모든 페이지가 바뀔 수 있다. 계산량을 없애기보다 이벤트 사이에 분산한다.
- 기존 한글 이탤릭 직렬화 결함과 다른 편집 화면의 전반적 리팩터링은 범위 밖이다.

## 구현 순서

1. 기존 변경 백업 및 baseline 테스트 확인.
2. 지속적인 저장소·레이아웃 매니저와 유효 페이지 범위 prefix를 가진 IncrementalPaginator 구현.
3. 현재 펼침면/커서까지 우선 계산, 나머지는 작은 페이지 묶음으로 유휴 갱신.
4. 페이지 NSTextView 직접 편집, 선택·입력 조합 유지, 문서에 변경 범위만 반영.
5. 문서 소유 Undo/Redo로 페이지 이동·모드 전환 뒤에도 수정 이력을 보존.
6. 쪽수 미확정 표시, 문서 교체 시 예약 작업 취소, 책갈피 위치 보정.
7. 기능·수명·조판 비교 테스트 및 긴 문서 측정, 빌드 검증.

## 사용자 동작과 상태

- 페이지 본문 클릭 → 커서 → 입력/삭제/붙여넣기. 읽기 모드는 유지된다.
- 방향키는 편집 커서 이동, Page Up/Down 및 기존 스크롤 제스처는 페이지 이동.
- 조합 중에는 입력 뷰를 교체하지 않는다. 조합 확정 뒤 커서가 있는 펼침면을 표시한다.
- 문서 저장은 원본 스타일을 저장한다. 페이지 계산 완료는 저장의 선행 조건이 아니다.
- 빈 문서도 한 페이지에 입력할 수 있다. 계산 중 전체 쪽수는 ‘…’로 표시한다.
- 문서 교체/모드 종료 시 이전 조판 작업이 새 화면에 반영되지 않는다.

## 인수 기준과 검증

- 타이핑·삭제·붙여넣기·Undo/Redo 이후 원본 텍스트와 저장된 Markdown이 일치한다.
- 새 입력에 읽기용 볼드·배율이 저장되지 않고 기존 사용자 서식은 보존된다.
- 동일 페이지 입력 시 storage/layoutManager/textView 객체를 재생성하지 않는다.
- 긴 문서 앞부분 수정 직후 전체 페이지 계산을 완료하지 않는다. 한 유휴 배치는 최대 2쪽이다.
- 최종 페이지 범위가 같은 문서를 처음부터 조판한 결과와 일치한다.
- 목표: 일반적인 한글 문장 입력에서 동기 처리 50ms 미만. 실제 측정 결과와 문서 크기를 개발 로그에 기록한다.
- 한글 marked text 유지, 경계 입력·전체 삭제·뒤쪽 추가·페이지 이동·문서 전환·수명 회귀를 검사한다.

## 트레이드오프와 후속 검증

페이지 하나의 조판 자체는 중단할 수 없으므로 거대 단락·첨부의 최대 지연은 별도로 측정한다.
먼 곳으로 직접 이동할 때에는 그 위치까지 필요한 앞쪽 조판 비용이 남는다.
독립 스레드 조판, TextKit 2 전환, 문단별 별도 레이아웃 엔진은 이번 변경에 도입하지 않는다.
실제 macOS 한글 입력기 후보창·트랙패드 감각은 자동 marked-text 테스트와 별도로 실사용 확인이 필요하다.

## 완료 결과

구현 완료. 전체 181개 테스트와 릴리스 빌드가 통과했다. 181,890 UTF-16 문자 문서의 입력 동기 처리 9.6ms, 화면 반영과 테스트 대기 포함 41.8ms를 확인했다. 검증 환경과 수동 확인 항목은 `docs/devlog/2026-10-25-editable-paged-reader.md`에 기록했다.
