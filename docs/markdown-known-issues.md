# 마크다운 저장의 알려진 문제

`shared/JenaNoteCore/markdown`은 맥 앱의 현재 저장 결과를 그대로 재현한다. 옮기는 일과 고치는 일을 섞지 않기 위해 아래 문제도 일부러 유지했다. 코드를 읽어 찾았고, 표에 적은 결과는 `shared/TestSupport/MarkdownCorpus.swift`에 기록돼 있다. 맥에서 `MarkdownCoreParityTests`로 확인하기 전까지는 예상 동작이다.

## 내용이 손상되거나 사라지는 문제

| 문제 | 입력 | 저장 결과 |
|---|---|---|
| 표 뒤 빈 줄이 저장할 때마다 늘어난다 | 표 + 빈 줄 + 글 | 저장마다 빈 줄 1개 추가 |
| 코드 블록 첫 줄이 비면 여는 펜스가 사라진다 | ` ``` `, 빈 줄, `abc`, ` ``` ` | `abc`, ` ``` ` |
| 코드 블록 끝 줄이 비면 닫는 펜스가 사라진다 | ` ``` `, `abc`, 빈 줄, ` ``` `, `끝` | 뒤따르는 글까지 코드가 된다 |
| 빈 코드 블록이 사라진다 | ` ``` `, ` ``` ` | 빈 줄 |
| 이웃한 코드 블록이 합쳐진다 | 코드 블록 2개가 빈 줄 없이 연속 | 코드 블록 1개 |
| 코드 블록 언어가 사라진다 | ` ```swift ` | ` ``` ` |
| 표 안의 기울임이 사라진다 | `| *a* |` | `a` |
| 표 안의 글자 색이 기본 글자색으로 바뀐다 (맥 앱만) | 색을 지정한 셀 | 화면 모드의 글자색이 지정색으로 저장 |

## 의도와 다를 수 있는 동작

| 동작 | 입력 | 저장 결과 |
|---|---|---|
| 표 머리글에 굵게 표시가 붙는다 | `| A |` | `| **A** |` |
| 큰 제목의 굵게 표시가 사라진다 | `# **a** b` | `# a b` |
| 이미지로 시작하는 제목이 본문이 된다 | `# ![a](b.png) 제목` | `![a](b.png) 제목` |
| 단어 안의 밑줄이 기울임이 된다 | `a_b_c` | `a*b*c` |

## 공유 코드와 맥 앱이 다른 점

표 안의 글자 색만 다르다. 공유 코드는 지정한 색을 유지한다. 맥 앱의 현재 값은 화면 모드에 따라 달라져서 재현할 수 없고, 재현할 이유도 없다.

## 줄바꿈 (CRLF)

맥 앱은 줄을 `\n`으로만 나눈다. CRLF 파일을 열면 줄 끝의 `\r`이 본문에 남고 `---\r`은 구분선으로 인식되지 않는다. Windows에서는 CRLF 파일이 흔하므로 Windows 앱은 파일을 읽을 때 줄바꿈을 정규화해야 한다.

## 고치는 시점

맥 앱을 공유 코드로 전환한 뒤 `MarkdownWriter`와 `MarkdownParser`에서 고친다. 그래야 두 플랫폼이 한 번에 고쳐진다. 고칠 때 말뭉치의 기대값도 함께 바꾼다.
