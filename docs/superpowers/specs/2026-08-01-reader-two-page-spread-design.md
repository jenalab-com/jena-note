# 읽기 모드 페이징 — 창 폭에 따른 2페이지 펼침면

- 날짜: 2026-08-01
- 상태: 승인됨 → 구현

## 목적

페이징 모드에서 창이 충분히 넓으면 좌·우 두 페이지를 나란히(책 펼침면처럼) 보여준다.
넓은 화면에서 한 페이지만 가운데 띄우고 좌우를 빈 여백으로 버리던 낭비를 없앤다.

## 동작 (승인된 결정)

- **자동 전환만.** 창(정확히는 읽기 영역) 폭이 두 단을 담을 만하면 2페이지, 좁아지면 1페이지로
  되돌아간다. 툴바 항목은 늘리지 않는다. → SettingsManager 변경 없음, 저장 상태 없음.
- **넘김은 펼침면 단위.** 왼쪽은 항상 짝수 인덱스(0-1, 2-3, …), 다음/이전은 ±2.
  마지막이 홀수 장이면 오른쪽 면은 비워 둔다.
- **페이지 분할은 그대로.** 2단은 순수한 표시 계층 변경이다.
- 스크롤 모드는 영향 없다.

## 왜 페이지 분할을 안 건드리는가

`rebuildPages()`가 만드는 `NSTextContainer` 배열은 (컬럼 폭 × 페이지 높이)에만 의존하며
호스트 폭과 무관하다. 2단은 **이미 만들어진 컨테이너 두 개를 나란히 얹는 것**뿐이므로
1단↔2단 전환에 재분할 비용이 들지 않는다. 페이지 경계·페이지 수도 두 모드에서 동일하다.

## 전환 임계 (순수 함수 + 히스테리시스)

```
진입: hostWidth ≥ 2×columnWidth + gutter(56) + 2×sideMargin(24)
이탈: hostWidth <  진입임계 − hysteresis(40)
```

이탈 임계를 따로 두는 이유: 경계 부근에서 창을 끌 때 1단↔2단이 매 프레임 뒤집히며
화면이 요동치는 것을 막는다. `ReaderMetrics.fitsSpread(hostWidth:columnWidth:currentlySpread:)`
순수 함수로 두고 `ReaderMetricsTests`로 못 박는다 (ADR-0006의 "순수 계산은 SPM 테스트" 결).

실제 값 감각 — 기본값(본문 15pt, 35자, 배율 1.0)에서 컬럼 ≈ 525pt이므로 읽기 영역
약 1154pt부터 2단. 모바일 폭(360 고정)은 824pt면 2단. 폰트를 키우면 컬럼이 넓어져
자연히 1단으로 되돌아간다 — 의도된 동작이다.

## 이어읽기·책갈피 (ADR-0008 유지)

- 앵커는 그대로 "왼쪽(=현재) 페이지 첫 글자의 문자 오프셋" 하나다. 새 좌표를 만들지 않는다.
- `visibleCharacterRange`만 펼침면일 때 **좌+우 합집합**을 돌려준다. 그러지 않으면 오른쪽
  면에 찍은 책갈피를 ⌘D가 "이 화면에 없다"고 판단해 중복으로 찍는다.
- 1단↔2단 전환은 페이지 번호가 아니라 앵커에서 페이지를 다시 찾으므로 읽던 문장이 남는다.

## 인디케이터

- 펼침면: `‹ 3–4 / 120 ›`
- 낱쪽(1단 또는 마지막 홀수 장): `‹ 120 / 120 ›`

## 곁들이는 손질 — 리사이즈 재분할 조건 좁히기

현재 `viewDidLayout`은 호스트 크기가 조금이라도 바뀌면 `rebuildPages()`(최대 9999 컨테이너
루프)를 돌린다. 2단이 창 폭에 반응하게 되면 가로 리사이즈가 잦아지므로, **페이지 높이와
컬럼 폭이 그대로면 재분할을 건너뛰고 재배치만** 하도록 조건을 좁힌다. 분할 결과가 이 둘에만
의존한다는 위 근거가 그대로 정당화 근거다.

## 변경 파일

| 파일 | 변경 |
|---|---|
| `ReaderMetrics.swift` | `spreadGutter`/`spreadSideMargin`/`spreadHysteresis` 상수, `fitsSpread(hostWidth:columnWidth:currentlySpread:)`, `spreadStart(page:)` |
| `ReaderViewController.swift` | `pageView` → `pageViews: [NSTextView]`, `isSpread` 상태, `showCurrentSpread()`, 넘김 ±2, `visibleCharacterRange` 합집합, 인디케이터 범위 표기, `viewDidLayout` 재분할 조건 |
| `ReaderMetricsTests.swift` | 임계·히스테리시스·펼침면 시작 인덱스 회귀 테스트 |

## 비고

- 좌우 페이지 사이는 여백(gutter)만 둔다. 구분선은 넣지 않는다 — 종이책 홈에 가깝고,
  다크 모드에서 선 색을 따로 고민할 필요도 없다.
- 툴바·설정·영속 상태가 늘지 않으므로 spec.md의 인수 기준에 새 항목이 생기지 않는다.
  AC-11(표시 설정이 바뀌어도 읽던 자리 유지)의 적용 대상이 하나 늘 뿐이다.
