# 작품 검색 즉시 사용과 백그라운드 요약

작성: 2026-10-28 · 사용자 승인 범위: 설계 후 구현

## 문제와 기대 결과

기원 작품에서 4,312개 원문 조각 중 413개 처리에 약 90분이 소요됐다(사용자 관찰). 현재 채팅은 모든 조각의 요약/발췌가 완료될 때까지 기다린다. 검색 준비와 상세 요약을 분리해, 요약 모델이 응답하지 않아도 원문을 읽은 뒤 채팅을 진행할 수 있게 한다.

## 가정과 기존 방침

- macOS 로컬 앱. 초기 요약은 Apple Intelligence로만 수행하며 외부 CLI로 자동 우회하지 않는다.
- 질문별 탐색과 최종 답변은 기존 사용자가 선택한 CLI 모델을 사용한다.
- 원문·설정이 최종 근거다. 기존 v2 캐시, 2,400바이트 조각, 수동 요약과 원고를 보존한다.
- 모든 변경은 저장소에서 구현한다. 실행 중인 앱 종료·설치 교체·기원 캐시 변경은 범위 밖이다.
- 첫 답변의 실제 시간은 디스크, 원고 크기, CLI 응답 시간에 의존한다. 고정된 초 단위 속도 향상은 보장하지 않는다.

## 결정

### 1. 검색과 요약의 생명주기 분리

`prepareForSearch`는 백그라운드에서 현재 등록 자료를 스캔하고, 완료 시점의 기존 요약을 내용 해시와 역할로 결합한 독립 스냅샷을 반환한다. 진행 중인 요약 완료를 기다리거나 취소하지 않는다. 매 요청 새 스캔으로 삭제·제외·원문 변경을 반영한다. UI는 기존 요청 토큰과 작품 설정 재검증으로 취소된 요청/다른 작품의 늦은 결과를 무시한다.

요약이 없는 조각의 검색 목록에는 원문 미리보기와 발췌 표기를 제공한다. 이를 완료된 요약으로 저장하지 않는다. 미래 화와 제외 자료는 기존 `eligible` 필터를 통과한 뒤 검색·프롬프트에 넣는다.

### 2. 질문별 원문 선검색

질문에서 제한된 개수의 검색어를 추출해 경로·원문·기존 요약을 백그라운드 큐에서 검색한다. 질문 검색 결과를 우선하고, 현재 문서와 직전 사용자 질문은 보조 검색에만 사용한다. 검색 결과의 인접 조각을 제한된 개수만 보충하고 직전 화의 최근 원문을 함께 제공한다. 검색 중 채팅을 취소하면 늦은 검색 결과가 CLI 호출로 이어지지 않는다.

- 허용된 전체 자료가 24조각 이하이고 원문 예산 안이면 탐색 CLI 왕복 없이 전체 원문을 최종 답변에 제공한다.
- 큰 작품은 관련 원문과 검색 목록을 첫 탐색 호출에 넣는다. 기존 최대 4회/240초 제한과 원문 근거 표시를 유지한다.
- 검색 누락 가능성이 있으므로 큰 작품의 단순 키워드 일치만으로 충분하다고 단정하여 탐색을 생략하지 않는다.
- 요약 생성은 답변 경로의 의존성이 아니다. 검색 결과를 백그라운드 요약 우선순위에 반영한다.

### 3. 요약 우선순위

최근 질문의 관련 조각 → 열린 문서 및 직전 화 → 기존 순서로 미완료 조각을 선택한다. 현재 진행 중인 추론은 끝까지 진행하고 다음 작업부터 새 순서를 적용한다. 내용 해시 기반 재사용·중복 처리 방지·실패 발췌의 명시적 재시도 계약은 유지한다. 연속 질문으로 뒷자료가 늦어질 수 있지만 질문 중단 후 전체 준비는 계속된다.

### 4. 저장 비용과 상태 표시

매 조각 전체 JSON 저장을 8회 완료/5초 간격으로 묶고, 최초 스캔·정상 완료·명시적 중지·오류에서는 저장한다. 정상적인 중지/재개는 완료된 요약을 보존한다. 비정상 종료 시 마지막 저장 이후 일부 요약은 재생성될 수 있다(최대 7회 추론 결과, 중복 원문 조각은 같은 결과 공유). 실제 타이머 실행은 메인 큐 상황에 따라 늦어질 수 있다. v2 파일 형식과 기존 성공 요약은 유지한다.

상태는 `원문 검색 준비 중`, `검색 사용 가능 · 백그라운드 정리 N/M조각`, `정리 완료`, `정리 중단/실패`로 구분한다. 완료 수는 AI 요약과 실패 발췌를 포함하므로 상세 개수를 별도 표시한다. 중지 후에도 검색 요청은 가능하며, 채팅 취소가 작품 백그라운드 작업을 취소하지 않는다.

## 대안과 보류

- 전체 요약 완료 대기: 사용자 관찰상 약 하루 대기가 발생해 기각.
- 질문 관련 요약 완료 대기: 첫 질문에 같은 지연을 옮기므로 기각.
- 큰 조각/추론 병렬화: 문맥 한도·품질·처리량 실측이 필요하고 캐시 재사용에 영향을 주므로 보류.
- 벡터 검색, 형태소 분석기, 요약 모델 교체: 이번 단계는 기존 로컬 문자열 검색을 확장하며 새 모델/서비스 의존성은 도입하지 않는다.
- ETA: 실제 추론/실패 시간 통계가 없는 상태에서 부정확한 예상 시간을 표시하지 않는다.

## 인수 기준과 검증

1. 요약 응답을 보류한 테스트에서 검색 준비와 최종 채팅이 완료된다. 채팅이 기다리는 요약 호출 수는 0이다.
2. 작은 작품의 탐색 CLI 호출은 0회이고 큰 작품의 첫 탐색 프롬프트에 관련 원문이 들어간다.
3. 늦은 요약·취소·설정 변경이 다른 요청에 결과를 섞지 않는다. 삭제/변경된 원문과 미래 화 제외를 검사한다.
4. 질문 우선순위가 다음 미완료 조각에 반영되며 진행 중인 호출은 취소하지 않는다.
5. 정상 완료/중지 후 기존 성공 요약이 재사용되고 저장 횟수가 조각 수보다 작다.
6. 전체 단위/가짜 CLI 통합 테스트와 릴리스 빌드로 검증한다. 실제 기원 작품 성능과 모델 품질은 실사용 측정 항목으로 남긴다.
