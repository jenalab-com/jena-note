# 작품 초기 파악: Foundation Models 설계 검토

작성: 2026-10-28 · 구현 전 결정 · ADR-0016

## 문제와 목표
파일을 열 때마다 CLI로 작품 전체를 요약하면 집필에 쓸 외부 AI 사용량을 준비 작업에 소모한다. 작가는 폴더만 등록하고 초기 파악을 기다리면 된다. 초기/증분 요약의 외부 CLI 호출 수를 0으로 만들고, 변경 없는 파일의 재요약 수를 0으로 유지한다. 실제 질문의 원문 탐색과 집필/수정 모델 선택은 유지한다.

## 가정과 검토 근거
- macOS 앱, 단일 프로세스, 작품 수십~수백 화. 원본과 작품 설정이 권위 데이터이며 인덱스는 재생성 가능한 캐시다.
- 배포 앱 최소 OS macOS 13은 유지(Swift 패키지 빌드 타깃은 11). Foundation Models는 macOS 26 이상에서만 사용하고 런타임 가용성을 확인한다. Xcode 26 SDK가 없는 빌드는 조건부 컴파일로 원문 검색만 제공한다.
- Apple의 4,096토큰 문맥에는 지시/원문/출력이 함께 들어간다. 기존 12KB 조각은 한국어 약 4천 자로 출력 여유가 없어 축소해야 한다.
- 한국어 소설의 사실 보존 품질 및 대규모 최초 완료 시간은 실측 대상이며 속도/정확도 우위를 보장하지 않는다.
- [생성 API](https://developer.apple.com/documentation/foundationmodels/generating-content-and-performing-tasks-with-foundation-models), [문맥 한도](https://developer.apple.com/documentation/technotes/tn3193-managing-the-on-device-foundation-model-s-context-window). 현재 설치된 26.5 SDK의 availability, cancellation, maximumResponseTokens 계약을 함께 검토했다.

## 선택과 대안
1. **선택: Foundation Models 온디바이스 요약 + 실패 시 원문 발췌 인덱스.** 초기 파악에 CLI 사용량이 발생하지 않으며 지원되지 않는 환경도 글쓰기를 계속할 수 있다.
2. CLI 자동 우회: 편하지만 알리지 않은 외부 호출/사용량이 생겨 제외.
3. 모델 사용 불가 시 전체 요청 차단: 플랫폼 조건 때문에 집필이 막히므로 제외.
4. Writing Tools: 사용자 대화형 편집 UI에는 적합하지만 백그라운드 색인 서비스에는 Foundation Models가 적합.

## 처리 흐름과 책임
폴더 스캔 → 2,400 UTF-8바이트 이하 원문 조각 → 해시/역할/요약 규격으로 캐시 확인 → 온디바이스 세션에서 조각별 요약 → 원자적 저장. 원문은 전량 보존하고 줄 번호 및 미래 화 필터를 유지한다.
- 인덱스 저장소에서 AIProvider/model 의존성을 제거한다. 주입 가능한 요약 경계는 passage → 요약 본문/출처/사유다.
- 각 조각마다 새 LanguageModelSession을 만들어 대화 누적과 작품 간 사실 혼합을 방지한다. 도구는 제공하지 않는다. 본문은 지시가 아닌 자료로 전달한다.
- 프롬프트는 설정의 규칙·금지·예외 또는 해당 조각의 인물·사건·상태 변화만 추출하도록 구분한다. 출력은 최대 512토큰, 저장은 최대 900자. 2,400바이트 제한은 토큰 수와 동일하지 않으므로 문맥 오류도 발췌로 안전하게 처리한다.
- 앱 전체 온디바이스 추론은 직렬로 실행하고, 작품별 기존 취소/진행률/중단 후 재개 규약을 유지한다. 한 조각 120초를 넘으면 취소하고 발췌 처리한다. SDK 취소는 협력적이며 즉각 강제 종료를 보장하지 않는다.
- AI 요약은 검색 힌트이며 사실의 최종 근거는 원문이다. 검색/읽기/최종 답변은 기존 CLI 경로다.

## 상태와 복구
- 기본/빈 폴더: 로컬 스캔, 파일 0개도 정상 완료.
- 준비 중: 기존 한 줄 진행률과 중지 유지.
- 지원 불가/Apple Intelligence 꺼짐/모델 준비 중: 이유를 기록하고 원문 발췌로 준비 완료, 외부 AI 호출 없음.
- 조각별 생성 오류/빈 응답/거절/시간 초과: 해당 조각만 원문 발췌. 원본을 수정하거나 버리지 않는다.
- 발췌는 AI 요약으로 표시하지 않으며 목록에 구분한다. 일부 발췌가 있어도 질의는 원문 검색으로 진행한다.
- 재시도는 발췌 조각만 대상으로 한다. 자동 재진입마다 같은 실패를 반복하지 않으며 모델 가용성이 달라지면 발췌를 재시도한다. 성공한 AI 요약은 유지한다.
- 파일 접근/캐시 저장 오류는 기존 실패 표시, 취소는 진행 중 세대를 무효화하고 늦은 응답을 반영하지 않는다.

## 캐시와 호환
인덱스 v2로 변경. 이전 12KB/v1 캐시는 원본에서 새로 구성하되 기존 수동 요약 파일은 그대로 둔다. 캐시에 요약 방식(apple/excerpt), 발췌 사유 및 가용성 서명을 기록한다. 모델 가용성 변화는 발췌만 무효화한다. 외부 CLI 사용량 누적 필드는 초기 인덱스에서 제거하고 UI는 기기 내 요약/원문 발췌 개수를 표시한다. OS 모델 업데이트만으로 전체 캐시를 자동 재생성하지 않으며 요약 지시/분할 규격 변경 시 버전을 올린다.

## 인수 기준
- 초기 및 저장 후 재준비에서 CLI 호출 0, 변경 없는 성공 요약 재호출 0.
- 실제 지원 모델에서 한국어 조각 요약을 실행해 결과/시간을 기록; 불가하면 원인과 미검증 범위를 기록.
- 한글/이모지/긴 한 줄 원문 복원 일치, 조각 제한 준수.
- 사용 불가/실패/취소/재시도/캐시 재사용 및 가용성 전환 테스트.
- 테스트용 로컬 요약 + 실제 CLI 프로세스 어댑터로 원문 탐색/답변 통합 확인. 미래 화 유출 없음, 외부 사용량은 탐색/답변만 집계.
- 전체 회귀 테스트와 릴리스 빌드. 구형 OS 런타임 실기 검증과 대규모 작품 품질 평가는 별도 기록.

## 범위 밖
벡터 DB, 파일 전체를 한 번에 요약, 외부 모델 자동 우회, 기존 집필 AI 교체, 원고 자동 수정, 설치 앱 교체/릴리스.
